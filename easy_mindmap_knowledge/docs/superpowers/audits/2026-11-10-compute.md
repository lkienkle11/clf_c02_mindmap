## 3. Findings that can change an answer (verified by the orchestrator)

**F1. `q_9e6c9d987920` (Q25), key C "Operating system patches": no option is correct.** The question: "Which responsibility belongs to AWS when a company hosts its databases on Amazon EC2 instances?" Options: A database backups, B database software patches, C operating system patches, D operating system installations. The AWS shared responsibility page says "Customers that deploy an Amazon EC2 instance are responsible for management of the guest operating system (including updates and security patches)"; backups and database software are the customer's too, and the customer chooses the operating system image it launches. Source: https://aws.amazon.com/compliance/shared-responsibility-model/. Both checkers: wrong, none correct (high). The current explanation and note C say "the exam expects" the opposite, which has no support.

**F2. `q_63c23e178263`, key A "Amazon EC2": RDS is also supported.** The question: "Which AWS service uses AWS Compute Optimizer to provide sizing recommendations based on workload metrics?" (A EC2, B RDS, C Lightsail, D Step Functions). The Compute Optimizer page lists, among the supported resources, "Amazon Aurora and Amazon Relational Database Service (Amazon RDS) databases"; Lightsail and Step Functions are not listed. Source: https://docs.aws.amazon.com/compute-optimizer/latest/ug/what-is-compute-optimizer.html. So both A and B are right today. Codex: outdated [A, B]; Haiku: ambiguous [A, B].

**F3. `q_7e665a1faa9c`, key C "AWS App Runner": closed to new customers.** The question asks for a managed service that builds container images from source code and deploys them. The App Runner guide says "AWS App Runner is no longer open to new customers. Existing customers can continue to use the service as normal" and recommends Amazon ECS Express Mode, which deploys a prebuilt container image. The Elastic Beanstalk page says that in Cluster mode "you provide a container image, or source that Elastic Beanstalk builds into one". Sources: https://docs.aws.amazon.com/apprunner/latest/dg/apprunner-availability-change.html and https://docs.aws.amazon.com/elasticbeanstalk/latest/dg/Welcome.html. So for a new company, A (Elastic Beanstalk) is the service that meets the requirement; C still works for existing customers. Haiku: outdated [A]; Codex: ambiguous [A, C].

**F4. `q_3979d8ab2d09`, key D "Amazon EC2": Lightsail matches the wording.** The question: "...use application stacks to run a workload... use pre-configured instances. Which AWS service?" (A Lightsail, B Athena, C Outposts, D EC2). The Lightsail guide says you "click-to-launch a simple operating system, a pre-configured application, or development stack, such as WordPress, Windows, Plesk, LAMP, Nginx". Source: https://docs.aws.amazon.com/lightsail/latest/userguide/what-is-amazon-lightsail.html. EC2 launches AMIs, which the documentation does not describe as "application stacks". The current note A already concedes Lightsail is a valid match. Both checkers: ambiguous [A, D].

**Not accepted:** Codex said Lambda MicroVMs make a 4 to 5 hour job possible (`q_1a29d1e1d12b`, `q_e8576e00ad1a`). The MicroVM page I opened gives no maximum duration, and the documentation I could find says a standard Lambda function runs at most 15 minutes (900 s) and Lambda Managed Instances up to 90 minutes for asynchronous invocations. Without evidence the keys B stay. Nine other "ambiguous" verdicts (for example Spot against On-Demand when the stem does not exclude interruptions, ELB scaling its own capacity) are rare readings; keys stay.
