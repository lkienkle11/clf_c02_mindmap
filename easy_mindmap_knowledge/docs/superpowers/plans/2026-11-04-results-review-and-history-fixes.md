# Results review, history and lesson-navigation fixes — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Result and history screens show every option with the user's pick marked and a per-option explanation for all 798 questions; fix the duplicate chart table, rework "most-missed" into a dialog, and make "Next" on a topic's last lesson open Practice.

**Architecture:** Explanations live in a new overlay `content/explanations/<topic>.json` (questionId → `{ explanation?, optionNotes? }`) merged into the catalog by `bundled.ts`, so `content/questions/imported.json` (regenerated by `scripts/import-cards`) is never hand-edited. One shared `OptionReview.svelte` renders options for the immediate result, the history detail and the new dialog. All other work is small, isolated Svelte/TS changes with tests first.

**Tech Stack:** Svelte 5 (runes), TypeScript, Tailwind v4 tokens, vitest + @testing-library/svelte, Tauri (no native change).

**Spec:** `docs/superpowers/specs/2026-11-04-results-review-and-history-fixes-design.md`

## Global Constraints

- Svelte 5 runes only; run `svelte-autofixer` (svelte MCP) on every touched `.svelte` file until clean.
- UI strings go in BOTH `src/i18n/en.json` and `src/i18n/vi.json`; question text and explanations stay English (`lang="en"`).
- No new dependency. No change to grading, scheduling, unlock rules or the DB schema.
- Correctness is never colour-only: text badges plus ✓/✗.
- Imports use the `@/` alias. Tests: `npm test`; types: `npm run check`. Both must be green at the end of every task.
- Commit messages follow the repo's Commitlint rules from the root `CLAUDE.md`: `type(scope): description` with body sections **Scope / What did / Reviewed / Tested**, and no AI attribution or co-author trailers (this overrides any default trailer).
- Content is factual AWS CLF-C02 material: every note must be correct for current AWS; no "all of the above"-style filler; one short sentence per option note.

## Review Focus

- A question with no overlay entry (or with `explanation` only) must still render: fallback to `explanation`, no crash, no empty "Explanation" heading.
- Multi-answer question where the user picked one right and one wrong option: each option gets its own badge.
- Attempt row referencing a question id no longer in the catalog: detail and dialog show the id, not a crash.
- Most-missed dialog with search matching nothing: shows an empty message, page indicator "0 of 0", Prev/Next disabled.
- Changing search/topic filter while on page 3: resets to page 1, never shows an empty out-of-range page.
- Last lesson of a topic whose required lessons are unread (opened via an optional lesson): Practice button disabled with the reason, not silently navigating.

**Rules for each entry:**
- `explanation`: 1–3 sentences, English, explains the reasoning for the correct answer. Imported questions need it; authored questions keep theirs unless the overlay supplies a better one (overlay wins).
- `optionNotes`: one entry for EVERY option key of the question (right and wrong), one short sentence each; wrong-option notes say why it fails for THIS scenario (e.g. CloudFront is a CDN cache, not compute near a studio); correct-option notes say what makes it fit. For `orderDependent` questions, state the required order in `explanation`.
- No claims that cannot be checked against official AWS docs; when unsure about a fact, use the `web-research` skill against docs.aws.amazon.com before writing it.
